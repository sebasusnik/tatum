# Module parameters

Values are floats in the listed range. Parameters with a unit column can be
written that way instead, which is the readable form: `cutoff 800hz`,
`attack 20ms`, `release 1.5s`, `osc2_pitch -12st`. Any 0..1 parameter also
takes a percentage (`resonance 80%`) and any gain takes decibels (`level 6db`).
`choice` params take an option name
(`waveform half_sine`); a numeric value encodes as index / (options - 1).
FM modules also accept `op<N>_envelope <attack> <decay> <sustain> <release>` as a
shorthand for the four per-operator envelope params.
Generated by `tatum params`; do not edit by hand.

## effects and nodes

Used in chains (`out > saturate(0.3) > master`, buses, `master { in > ... > out }`) and,
for sources and envelopes, inside `instrument { }` graphs. Positional arguments in order,
then `name=value` options. Unknown names and out-of-range values are compile errors.


Two options apply to every node that can sit in a chain, on top of the ones
listed below:

- `wet=` 0..1 (default 1) — dry/wet. At 0 the node is **bypassed**: it is not
  processed at all, so a chain of effects that are switched off costs nothing.
  At 1 it replaces the signal, and in between it is blended against the dry.
  Changing only `wet=` applies inside the bar with no hot-swap, so it is how a
  live set switches an effect in and out without restarting the voices.
  It is a different thing from the `mix` that `phaser` and `vowel` declare,
  which is those nodes' own internal wet amount.
- `as <name>` — name the node, after the closing parenthesis:
  `> autowah(0.9, base=450hz) as wah`. A name is what `auto <track>.<name> wet`
  points at, and it survives someone inserting another node earlier in the
  chain, which a position does not. Two nodes in one chain cannot share a name.
