# `.synth` reference

A `.synth` file is the intermediate representation the engine plays. It is strict:
unknown names and out-of-range values are compile errors, never silent no-ops.
Module parameters are documented in [PARAMS.md](PARAMS.md), generated by `synth params`.

```
synth check song.synth          # parse + compile, prints errors with line numbers
synth render song.synth -o out.wav
synth params fm                 # parameter reference for one module type
synth params --json             # machine-readable registry (for tools and agents)
```

## Globals

```
tempo 124
meter 4/4
scale A minor          # major | minor | dorian | mixolydian | pentatonic_minor
swing 0.56             # 0.5 straight .. 0.75 hard shuffle
humanize 0.05 timing 0.02
sidechain 0.4

# Global send effects, fed by each track's delay_send / reverb_send
delay sync=dotted_eighth feedback=0.45 filter=0.5   # sync: free | quarter | dotted_eighth |
                                                    #       eighth | sixteenth (default) | triplet_eighth
                                                    # time=0.3 (seconds) applies when sync=free
reverb size=0.7 damp=0.4 predelay=20                # predelay in ms
```

## Modules

Built-in instruments. Values are floats in the range listed in PARAMS.md.
Choice parameters accept the option name.

```
module bass acid {
    cutoff 0.25
    resonance 0.8
    osc1_wave saw            # saw | square
    lfo_target cutoff        # cutoff | pitch | amplitude
}

module fm bell {
    algorithm two_op         # serial3_plus_carrier | dual_pairs | two_op | additive |
                             # serial4 | dual_mod | triple_mod | pair_plus_two
    waveform half_sine       # sine | half_sine | abs_sine | quarter_sine
    op0_envelope 0.001 0.2 0.0 0.3    # attack decay sustain release for operator 0
}

module keys pad { voice_mode unison }      # poly | unison | octave | fifth | ringmod
module beats kit { kick_level 1.0 stutter_drum snare }
```

A typo produces `line 12: module 'acid' (bass): unknown parameter 'cutof'. Did you mean 'cutoff'?`

## Patterns

Sixteen steps per bar by default. Melodic steps are scale degrees (`1.2` = degree 1,
octave 2) or absolute notes (`A2`), with optional `:velocity`. Rows concatenate, so a
pattern can span several bars (32 steps = 2 bars). Each track loops its own pattern.
A note or chord followed by ties that loops back onto the same note keeps sustaining
instead of retriggering, which is how pads are written: one chord, fifteen ties.

```
pattern riff { 1.2:0.9  -  ~5.2:0.8  ..  [1.3 3.3 5.3]:0.6  ..  ..  .. }
```

| token | meaning |
|-------|---------|
| `-` | rest |
| `..` | tie: hold the previous step |
| `~note` | slide: glide into this note without retriggering the envelope (303 style). The previous note is held until the slide. Bass modules glide at their `glide` rate; other instruments fall back to a normal retrigger. |
| `[a b c]` | chord |
| `1.2:0.8(cutoff=0.4, edepth=0.3, res=0.6, gate=0.5)` | per-step parameter lock (bass filter and gate) |

Drum patterns use labeled lanes:

```
pattern beat {
    kick:  X - - -  x - - -  X - - -  x - x:0.6 -
    snare: - - - -  X - - -  - - - -  X - - -
    hat:   x x x x  x x x x  x x x x  x x x x
}
```

`X` accent, `x` normal, `o` ghost, `x:0.6` explicit velocity, `x?0.5` probability, `x*2` roll.

## Tracks

```
track lead {
    play riff
    using bell
    level 0.7  pan -0.2  gate 0.8  velocity 0.9
    delay_send 0.2  reverb_send 0.1
    arp up rate=16 gate=0.6 octaves=2
    out > saturate(0.3) > master
}
```

### Arpeggiator

`arp <mode> [rate=N] [gate=F] [octaves=N]`

- **mode**: `up`, `down`, `updown`, or `off` (a scene track can turn off an inherited arp).
- **rate**: notes per bar, one of `4`, `8`, `16` (default), `32`. Follows tempo changes.
- **gate**: fraction of each arp step the note is held, `0.1`..`1.0` (default `0.6`).
- **octaves**: `1`..`4`, the held notes are repeated in higher octaves (default `1`).

The pattern supplies what is held: a single note or a chord, extended with `..` ties.
The arp cycles through those notes and stops at the next rest or when the track gate
expires. Scene tracks inherit the arp from the global track definition.

## Scenes and arrangement

```
scene drop {
    tempo 128                            # optional per-scene tempo
    reverb_mix = 0.3                     # wet level of the global sends for this scene
    delay_mix = 0.2
    auto acid cutoff 0.2 > 0.6 > 0.2     # linear (2 values) or triangle (3 values)
    auto drums level 1.0 > 0.0           # track (or instrument) level fade
    auto reverb_mix 0.1 > 0.5
    track drums { play beat using kit }
    track acid  { play riff using acid }
}

arrange { intro x4  drop x8  outro x2 }
```

A scene reconfigures existing tracks by name, in any order; a track not declared at
top level is a compile error, and so is an unknown override. Tracks the scene does not
mention are silent for its duration. `auto` runs over the scene's whole length in the
arrangement and its targets are validated: the module and parameter must exist.

## Livecoding semantics

When the source is re-evaluated while playing:

- Parameter, level, pan, velocity, gate, tempo, swing and humanize edits apply instantly.
- Deleting a parameter line restores the registry default instantly.
- Any other edit (pattern notes, scenes, routing, arp, new modules) is a structural change:
  the new song is compiled and swapped in at the next bar boundary with a short crossfade.
